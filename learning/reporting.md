# Learning Notes: Reporting

Working notes on writing higher-quality vulnerability reports, one of the core SR Summer goals (see
[README](../README.md#goals-for-sr-summer-2026)). General learnings only; specific report drafts live
in the private `reports/` directory.

## Topics to cover

- [ ] Structuring a report: summary, root cause, attacker preconditions, PoC, impact, severity
      justification.
- [ ] Writing root-cause explanations that a triager unfamiliar with the codebase can follow.
- [ ] Severity classification frameworks used by Immunefi (and how to map impact to severity
      correctly).
- [ ] Common reasons reports get downgraded or rejected (vague impact, missing preconditions,
      duplicate/known issue) and how to avoid them.
- [ ] Writing for "primacy of impact" vs. "primacy of rules" programs, what changes in framing.
- [ ] Using Immunefi Studio effectively during triage/communication.
